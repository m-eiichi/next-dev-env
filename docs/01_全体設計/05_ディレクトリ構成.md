## 2. `src/` の構成方針

<!-- 例として一般的な分け方を記入してある。採用するものに合わせて直す -->

`src/server/` の外を**フロント**、中を**バック**に分ける（[ADR-008](../04_設計判断/ADR-008_フロントとバックの分け方.md)）。

**フロント**

| ディレクトリ | 置くもの | 例 |
| ------------ | -------- | -- |
| `src/app/` | ルーティング用のファイル（`page` / `layout` / `loading` / `error` / `route` など）と、その画面だけで使う部品。Server Action は置かない | |
| `src/app/(group)/` | URL に影響しないグループ分け（route group）。レイアウトを分けたいときに使う | `(auth)`, `(admin)` |
| `src/app/**/_components/` | その画面だけで使うコンポーネント。先頭が `_` のフォルダはルーティングの対象外 | |
| `src/components/atoms/` | 複数の画面で使う、それ以上分けられない最小の部品。shadcn/ui の基本部品もここ | `button/`, `input/`, `badge/` |
| `src/components/molecules/` | atoms を組み合わせた部品 | `dialog/`, `form/`, `search-box/` |
| `src/components/organisms/` | 画面の一区画になる大きな部品。業務の知識を持ってよい | `header/`, `post-card/` |
| `src/hooks/` | Custom Hooks | |

**バック**

| ディレクトリ | 置くもの | 例 |
| ------------ | -------- | -- |
| `src/server/entry/queries/` | 取得の関数（入口）。Server Component から呼ぶ | `post/list-posts.ts` |
| `src/server/entry/actions/` | Server Action（入口）。1 ファイルに 1 つ | `post/create-post.ts`, `types.ts` |
| `src/server/entry/api/` | Route Handler の中身（入口）。`src/app/**/route.ts` から読み込む | `v1/posts.ts` |
| `src/server/application/command/` | 更新のユースケース（アプリケーション層。CQRS の command） | `post/create-post.usecase.ts` |
| `src/server/application/query/` | 読み取りのクエリと、Query Service のインターフェース（アプリケーション層。CQRS の query） | `post/list-posts.query.ts`、`post/post-query-service.ts` |
| `src/server/application/dto/` | DTO（command と query の両方で使う） | `post/post.dto.ts` |
| `src/server/domain/` | エンティティ、値オブジェクト、リポジトリのインターフェース（ドメイン層。更新に使う） | `post/entity.ts` |
| `src/server/infrastructure/` | DB・認証サービスの実装（リポジトリと Query Service の実装）、DI コンテナ（インフラストラクチャ層） | `di/container.ts`、`database/post/post-query-service-impl.ts` |

**どちらにも属さない**

| ディレクトリ | 置くもの | 例 |
| ------------ | -------- | -- |
| `src/lib/` | 層に属さないユーティリティ | `cn()` |
| `src/proxy.ts` | リクエスト前の処理（旧 middleware） | |

- 層の分け方と依存のルールは [06 アーキテクチャ](./06_アーキテクチャ.md) を参照
- フロントが `src/server/` から import してよいのは、`src/server/entry/` の関数と DTO の型だけ

### 2.1 コンポーネントの置き場所

コンポーネントは、**何か所の画面で使うか**で置き場所を分ける。

| 置き場所 | 置くもの | 形 | 例 |
| -------- | -------- | -- | -- |
| `src/components/` | **複数の画面**で使う部品。atoms / molecules / organisms に分ける（下の「2.2」） | `{分類}/{名前}/index.tsx` | `src/components/atoms/button/index.tsx` |
| `src/app/**/_components/` | **その画面だけ**で使う部品 | `{名前}.tsx` | `src/app/(main)/posts/_components/post-list.tsx` |

- 最初は `_components/` に置き、2 つ目の画面で使うことになった時点で `src/components/` に移す（先回りして共通化しない）
- `_components/` の部品は、他の画面の `_components/` から import しない。使いたくなったら `src/components/` に移す
- 同じ機能の複数の画面（例: `posts/` の一覧と詳細）で使う部品は、その親のフォルダの `_components/` に置いてよい（例: `src/app/(main)/posts/_components/`）

#### フォルダ名の `_` について

| フォルダ | 先頭の `_` | 理由 |
| -------- | ---------- | ---- |
| `src/app/**/_components/` | 付ける | `src/app/` の中のフォルダは URL になる。`_` を付けると、Next.js がルーティングの対象から外す |
| `src/components/` | 付けない | `src/app/` の外なので、ルーティングと関係がない。shadcn/ui の初期設定（`@/components`）とも合わせる |

### 2.2 `src/components/` の構成

複数の画面で使うコンポーネントは、Atomic Design の考え方で 3 つに分ける。

| 分類 | 置くもの | import してよいもの |
| ---- | -------- | ------------------- |
| atoms | ボタン、入力欄、ラベルなど最小の部品 | atoms だけ |
| molecules | atoms を組み合わせた部品（ダイアログ、フォームの 1 項目など） | atoms、molecules |
| organisms | ヘッダー、一覧のカードなど画面の一区画 | atoms、molecules、organisms |

- 1 つのコンポーネントを 1 つのフォルダにし、本体は `index.tsx` にする（例: `src/components/atoms/button/index.tsx`）。import は `@/components/atoms/button`
- 迷ったら小さい方（atoms / molecules）に置き、大きくなったら上に移す

### 2.3 shadcn/ui の部品を追加する

#### 初回だけ: 初期設定

プロジェクトに `components.json` がない場合だけ、最初に 1 回実行する（すでにあれば不要）。

```bash
pnpm shadcn init
```

| 質問・設定 | 選ぶもの |
| ---------- | -------- |
| コンポーネントライブラリ | Base UI |
| import のエイリアス | 初期値のまま（`@/components`、`@/lib/utils` など） |
| `components.json` の `aliases.ui` | 初期値の `@/components/ui` のまま。`shadcn:add` はここに作られたファイルを atoms / molecules に移すので、変えると動かない |

- 実行すると `components.json` と `src/lib/utils.ts`（`cn()`）が作られ、`src/app/globals.css` に色などの CSS 変数が追加される。これらはコミットする

#### 部品の追加

`pnpm shadcn add` を直接使わず、`pnpm shadcn:add`（`scripts/shadcn-add.mjs`）で追加する。置き場所の層を最初に指定する。

```bash
pnpm shadcn:add atoms button input
pnpm shadcn:add molecules dialog
pnpm shadcn:add atoms button --overwrite   # すでにあるものを置き換える
```

| 動き | 内容 |
| ---- | ---- |
| 置き場所 | 指定したものは指定した層、依存として一緒に入ったもの（`dialog` に対する `button` など）は atoms に置く |
| import の書き換え | shadcn/ui が生成する `@/components/ui/xxx` の import を、移動先（`@/components/atoms/xxx` など）に書き換える |
| すでにあるもの | 手を入れている可能性があるので置き換えない。置き換えるときは `--overwrite` を付ける（手を入れた部分は消える） |
| 置ける層 | atoms / molecules だけ。organisms は shadcn/ui ではなく自分で作る |

- shadcn/ui は一度 `src/components/ui/` にファイルを作り、スクリプトがそこから移す。`src/components/ui/` が残っていたら、前回の追加が途中で失敗しているので中身を確認する
- `pnpm shadcn add` を直接使うと `src/components/ui/` に置かれたままになるので使わない

## 3. ファイル配置のルール

| 項目 | ルール |
| ---- | ------ |
| import のエイリアス | `@/*` → `src/*`（`tsconfig.json`） |
| ファイル名・フォルダ名 | 下の「4. ファイル名のルール」 |
| 同じ場所に置くもの（コロケーション） | 画面専用の部品は、その画面のフォルダに置く / 置かない |
| テスト | テスト対象と同じフォルダに `*.test.ts(x)` で置く。E2E テストはプロジェクト直下の `e2e/` に置く（[10 テスト](../02_共通設計/10_テスト.md)） |

## 4. ファイル名のルール

`src/` の下のファイル名とフォルダ名は、ls-lint（`.ls-lint.yml`）でチェックする。`pnpm lint:ls` で確認でき、CI でも実行する（[11 CI](../02_共通設計/11_CI.md)）。

### 4.1 ファイル

**ファイル名はすべて kebab-case にする。** コンポーネントのファイルも kebab-case にし、コンポーネント名（コードの中の名前）は PascalCase にする（[08 コーディング規約](../02_共通設計/08_コーディング規約.md)）。

| 対象 | ルール | 例 |
| ---- | ------ | -- |
| `src/components/` のコンポーネント | kebab-case のフォルダ + `index.tsx` | `atoms/button/index.tsx`, `organisms/post-card/index.tsx` |
| `src/app/**/_components/` のコンポーネント | kebab-case | `post-list.tsx`（中身は `export function PostList`） |
| それ以外（`.ts`） | kebab-case | `entity.ts`, `post-repository-impl.ts`, `use-posts.ts` |
| ユースケース（更新） | kebab-case + `.usecase.ts` | `create-post.usecase.ts` |
| クエリ（読み取り） | kebab-case + `.query.ts` | `list-posts.query.ts` |
| DTO | kebab-case + `.dto.ts` | `post.dto.ts` |
| テスト | テスト対象の名前 + `.test.ts(x)` | `entity.test.ts`, `post-list.test.tsx` |
| `src/app/` の Next.js の決まった名前 | kebab-case（Next.js の決まりどおり） | `page.tsx`, `layout.tsx`, `not-found.tsx`, `route.ts` |

kebab-case にそろえる理由:

- Next.js の決まった名前（`page.tsx` など）や shadcn/ui のコンポーネント名（`dropdown-menu` など）と、書き方が 1 つにそろう
- `.ls-lint.yml` に例外を作らずに済む
- 大文字・小文字だけを変える名前の変更（`postList.tsx` → `PostList.tsx`）は、Mac では Git が検知しにくくトラブルになりやすいが、すべて小文字ならこれが起きない

### 4.2 フォルダ

| 対象 | ルール | 例 |
| ---- | ------ | -- |
| 基本 | kebab-case | `value-objects`, `use-posts` |
| `src/app/` の動的ルート | `[名前]` / `[...名前]` / `[[...名前]]`（名前は英数字） | `[id]`, `[...slug]` |
| `src/app/` のグループ | `(名前)` | `(main)`, `(auth)` |
| `src/app/` のルーティング対象外 | `_名前` | `_components` |
| `src/app/` の並列ルート | `@名前` | `@modal` |

### 4.3 ルールを変えるとき

- `.ls-lint.yml` と、この表の両方を変える
- 新しい種類の拡張子（例: `.schema.ts`）を使い始めるときは、`.ls-lint.yml` の `src` と `app` の両方のブロックに追加する（下の階層の設定は上の階層の設定を丸ごと置き換えるため）
- インターセプトルート（`(.)photo` など）を使う場合は、`src/app` の `.dir` にルールを追加する
