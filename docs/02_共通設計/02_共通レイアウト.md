# 02 共通レイアウト

## 1. layout の階層

<!-- route group ごとにレイアウトを分ける場合の例。実際の構成に合わせて直す -->

```
src/app/layout.tsx              ルート（<html>, <body>, フォント, globals.css）
├─ (public)/layout.tsx          公開ページ用: ヘッダー + フッター
├─ (auth)/layout.tsx            ログイン画面など: ロゴだけの簡素なレイアウト
└─ (app)/layout.tsx             ログイン後: ヘッダー + サイドバー
```

| layout | 使う画面 | 含むもの |
| ------ | -------- | -------- |
| `src/app/layout.tsx` | 全画面 | `<html lang>`、フォント、`globals.css`、共通の `metadata`、ヘッダー、フッター |

- 画面が 1 つのうちは、ヘッダーとフッターをルートレイアウトに置いている。ログイン画面など別のレイアウトが必要になったら、上の route group の形に分ける

- `layout` は画面を移動しても再レンダリングされず、state が残る。画面を移動するたびに初期化したいものは `template.tsx` に置く

## 2. ルートレイアウトの設定

| 項目 | 現在の値（テンプレート） | 決定値 |
| ---- | ------------------------ | ------ |
| `<html lang>` | `en` | `ja` |
| フォント | Geist / Geist Mono（`next/font/google`） | Geist / Geist Mono。日本語はシステムのフォント（`globals.css` の `--font-sans`） |
| `metadata.title` | `Create Next App` | `{ template: '%s \| Next.js 開発テンプレート', default: 'Next.js 開発テンプレート' }` |
| `metadata.description` | `Generated by create next app` | DDD とクリーンアーキテクチャの考え方で層を分けた、Next.js App Router のプロジェクトテンプレート |
| favicon | `src/app/favicon.ico` | テンプレートのまま |

## 3. ヘッダー

| 項目 | 内容 |
| ---- | ---- |
| 表示する要素 | サイト名（`/` へのリンク）。グローバルナビ、ログイン状態は画面が増えたら追加する |
| 固定するか | 固定しない |
| モバイル | サイト名だけなので同じ表示 |
| コンポーネント | `src/components/organisms/header/index.tsx`（Server）。メニューの開閉を付けるときは、その部分だけ Client にする |

## 4. フッター

| 項目 | 内容 |
| ---- | ---- |
| 表示する要素 | 設計資料（`docs/README.md`）の案内。コピーライト、利用規約などへのリンクは必要になったら追加する |
| コンポーネント | `src/components/organisms/footer/index.tsx`（Server） |

## 5. ナビゲーション

| 項目 | 方針 |
| ---- | ---- |
| 画面内のリンク | `next/link` の `<Link>` を使う |
| 現在の画面の強調 | `usePathname()` で判定（Client Component） |
| パンくずリスト | 使う / 使わない |
| プログラムでの画面移動 | Server 側は `redirect()`、Client 側は `useRouter().push()` |
