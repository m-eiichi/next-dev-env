# 04 データ取得・更新

<!-- 全体の方針（Cache Components を使うかなど）は 01_全体設計/02_システム構成 に書く。ここは書き方のルール -->

## 1. データ取得

| 項目 | ルール |
| ---- | ------ |
| 取得する場所 | Server Component から、取得の関数（`src/server/entry/queries/`）を呼んで取得する。Client Component から取得するのは、リアルタイム更新などが必要な場合だけ |
| 取得の関数 | 1 つのデータにつき 1 つ。依存を組み立ててユースケースを呼び、DTO を返す（[06 アーキテクチャ](../01_全体設計/06_アーキテクチャ.md) の「4.1 入口」） |
| DB へのアクセス | データアクセス層（ユースケース）を通す。page から直接クエリを書かず、page でユースケースを組み立てることもしない |
| 認可 | データアクセス層の関数の中でもチェックする（[01 認証・認可](./01_認証・認可.md)） |
| 並列化 | 依存しない取得は `Promise.all` でまとめる |
| 待ち時間の表示 | 遅い部分を `<Suspense>` で囲み、先に表示できる部分から表示する |
| Client に渡すデータ | 必要な項目だけに絞る。パスワードのハッシュなどを props で渡さない |

- 秘密情報を扱うモジュールの先頭に `import 'server-only'` を書き、Client Component から誤って読み込めないようにする

## 2. キャッシュ

Cache Components を使う（[02 システム構成](../01_全体設計/02_システム構成.md) の「5」、[ADR-012](../04_設計判断/ADR-012_キャッシュの方式.md)）。データの取得は、何も指定しなければアクセスのたびに行われる（動的）。取得ごとに、下のどちらかを必ず選ぶ。

- **キャッシュする**: 取得の関数に `'use cache'` を付ける
- **キャッシュしない**: 取得する部品を `<Suspense>` で囲む（囲まないとビルドでエラーになる）

> 今のサンプル（`listExamples`、`listTechStack`）は、メモリ上の仮のリポジトリからすぐ結果が返るので、どちらも付けずにビルド時に作る部分に入っている。DB に切り替えたら、どちらかを付ける。

| データの種類 | キャッシュ | 書き方 | 再検証 |
| ------------ | ---------- | ------ | ------ |
| （例）ほぼ変わらないマスタ | する | `'use cache'` + `cacheLife('days')` | 更新時に `revalidateTag` |
| （例）一覧・詳細 | する | `'use cache'` + `cacheTag('posts')` | 更新時に `revalidateTag('posts')` |
| （例）ログインユーザー固有 | しない / 個別 | `'use cache: private'` | |
| 常に最新が必要 | しない | `<Suspense>` で囲んで動的に取得 | - |

- タグの命名: `エンティティ名` / `エンティティ名:ID`（例: `posts`, `post:123`）
- `'use cache'` と `cacheTag` / `cacheLife` は、取得の関数（`src/server/entry/queries/`）に書く
- `cacheLife` は省略せず、必ず書く（省略すると `default`（15 分ごとに作り直す）になり、読む人にわからない）

```ts
// src/server/entry/queries/tech-stack/list-tech-stack.ts（DB から取得するようになった場合の例）
export async function listTechStack(): Promise<TechStackItemDto[]> {
  "use cache";
  cacheLife("days");
  cacheTag("tech-stack");

  const useCase = new ListTechStackUseCase(container.techStackRepository());
  return useCase.execute();
}
```

| 制約 | 対応 |
| ---- | ---- |
| `'use cache'` の中（呼び出した先も含む）では `cookies()`・`headers()`・`searchParams` を使えない | 外で読んだ値を引数で渡す。どうしても渡せない場合は `'use cache: private'` |
| 引数と戻り値は、シリアライズできるものだけ（クラスのインスタンスは不可） | 取得の関数は DTO を返すので、そのままでよい。エンティティは返さない |
| ページの設定の `revalidate`・`dynamic`・`dynamicParams` は使えない | 時間での作り直しは `cacheLife`、見つからない URL は `notFound()` で扱う |
| ビルド時に作る部分で、現在時刻（`Date.now()` など）を読むとエラーになる | 読む部品を `<Suspense>` で囲む（下の「5.2」の TanStack Query もこれにあたる） |

## 3. データ更新（Server Action）

| 項目 | ルール |
| ---- | ------ |
| 置き場所 | 使う画面の数にかかわらず `src/server/entry/actions/{エンティティ名}/{操作名}.ts`（例: `post/create-post.ts`）。1 ファイルに 1 つ。`src/app/` の中には置かない |
| ファイル先頭 | `'use server'` |
| 最初にすること | 認証・認可のチェック → 入力のバリデーション（[05 フォーム・バリデーション](./05_フォーム・バリデーション.md)） |
| 戻り値 | 下の「戻り値の形」にそろえる |
| 更新後 | `revalidateTag` / `revalidatePath` / `refresh()` で画面を最新にする |
| 画面移動 | `redirect()` は `try/catch` の**外**で呼ぶ（中で呼ぶとエラーとして捕まってしまう） |

### 戻り値の形

```ts
type ActionResult<T = void> =
  | { ok: true; data: T }
  | { ok: false; message: string; fieldErrors?: Record<string, string[]> }
```

## 4. Route Handler（`route.ts`）

使うのは次の場合だけにする。

- 外部から呼ばれる API、Webhook（[09 外部公開 API](./09_外部公開API.md)）
- 画像やファイルのダウンロード
- Client Component から GET で取得する必要がある場合

画面から使う Route Handler は `src/app/api/internal/` に置き、外部公開 API（`src/app/api/v1/`）は画面から呼ばない。

- 中身は `src/server/entry/api/` に書き、`route.ts` はそれを読み込むだけにする（例: `export { GET } from "@/server/entry/api/v1/posts"`）
- 画面用のものは `src/server/entry/api/internal/` に置く（例: `src/app/api/internal/examples/route.ts` → `src/server/entry/api/internal/examples.ts`）

## 5. クライアントでの取得（TanStack Query）

画面を開いた後に、ブラウザ側で何度も取り直す必要がある場合だけ使う（[ADR-002](../04_設計判断/ADR-002_画面とサーバーのつなぎ方.md)）。見本は [SCR-011 サンプル検索](../03_画面設計/SCR-011_サンプル検索.md)。

| 使う | 使わない |
| ---- | -------- |
| 定期的な取り直し（通知の件数、処理の進み具合）、入力に合わせた候補の表示、無限スクロール | 画面を開いたときの表示（Server Component）、フォームの送信（Server Action）、更新後に画面を最新にする（`revalidateTag` / `refresh()`） |

### 5.1 つなぎ方

```
Client Component（useQuery）
  → fetch("/api/internal/...")               src/app/api/internal/**/route.ts（読み込むだけ）
  → src/server/entry/api/internal/...        入力のバリデーション、依存の組み立て、ユースケースの呼び出し
  → ユースケース → …
```

- `src/server/entry/queries/` は `server-only` なので、ブラウザからは呼べない。同じユースケースを Route Handler からも呼ぶ
- Server Action を `queryFn` に使わない（POST で、1 つずつ順番に実行されるので取得に向かない）

### 5.2 書き方のルール

| 項目 | ルール |
| ---- | ------ |
| 初期表示 | Server Component で `src/server/entry/queries/` の関数を呼んで取得し、Client Component に props で渡して `initialData` にする。最初からブラウザで取得しない |
| Suspense | `useQuery` を使う Client Component は `<Suspense>` で囲み、`fallback` には初期表示のデータで描いた表示を渡す。TanStack Query は `initialData` を受け取るときに現在時刻を読むため、囲まないとビルドでエラーになる（上の「2. キャッシュ」の制約）。囲んだ部分はブラウザで描かれ、HTML には `fallback` が入る |
| `useQuery` を書く場所 | 使う Client Component の中。複数の画面で使うようになったら、Custom Hook にして `src/hooks/` に移す |
| query key | `["エンティティ名", { 条件 }]`（例: `["examples", { keyword }]`）。1 つ目はキャッシュのタグ名（上の「2. キャッシュ」）とそろえる |
| レスポンスの形 | 外部公開 API と同じにする（[09 外部公開 API](./09_外部公開API.md) の「6. リクエスト・レスポンスの形」）。成功は `{ data: T }`、失敗は RFC 9457（Problem Details）＋ `code` ＋ `errors`（[ADR-010](../04_設計判断/ADR-010_APIのエラーの形.md)）。失敗のレスポンスは `src/server/entry/api/problem-details.ts` の `problemResponse()` で作る |
| 入力に合わせて取得する場合 | 入力が 300 ミリ秒ほど止まってから取得する。取得中は `placeholderData: keepPreviousData` で前の結果を表示したままにする |
| 型 | 下の「5.3 レスポンスの型」 |

### 5.3 レスポンスの型

レスポンスの型をどう持つかは、呼び出し元とデプロイの関係で決める（[ADR-009](../04_設計判断/ADR-009_APIのレスポンスの型.md)）。

| 場合 | レスポンスの型 | 理由 |
| ---- | -------------- | ---- |
| 画面用の Route Handler（`/api/internal/`）。自分の画面だけが使い、同じリポジトリから一緒にデプロイする | **共有する**。入口のファイルで export し、フロントは `import type` で使う | フロントとバックが常に同じ版なので、型を共有すればずれが起きない |
| 外部公開 API（`/api/v1/`） | **DTO とは別に、公開用の型を作る**（[09 外部公開 API](./09_外部公開API.md) の「6」） | 画面の都合で DTO を変えたときに、外部の利用者を壊さないため |
| バックを別のサーバーに分けたとき | **スキーマ（OpenAPI、Zod のスキーマなど）から型を作る**。受け取る側で実行時にもチェックする | デプロイの時期がずれるので、ビルド時にしかチェックされない TypeScript の型だけでは約束を守れない |

`/api/internal/` の書き方:

```ts
// src/server/entry/api/internal/examples.ts（入口）
export type ListExamplesResponse = { data: ExampleDto[] };

export async function GET(request: Request): Promise<Response> {
  // ...
  return Response.json({ data: examples } satisfies ListExamplesResponse);
}
```

```ts
// src/app/example/search/_components/example-search.tsx（フロント）
import type { ListExamplesResponse } from "@/server/entry/api/internal/examples";

const body: ListExamplesResponse = await response.json();
```

- 返す値に `satisfies` を付け、export した型と実際に返す値がずれないようにする
- フロントでは必ず `import type` で読み込む（入口のファイルは `server-only` なので、値として読み込むとビルドエラーになる）
