# ADR-011 ファイル直下の関数は `function` で書く

| 項目 | 内容 |
| ---- | ---- |
| 状態 | 採用 |
| 日付 | 2026-09-25 |
| 決めた人 | |

## 背景

プロジェクトのコードは、たまたますべて `export function` で書かれていたが、資料に決まりはなかった。`export const` ＋アロー関数の方が好みという意見もあり、どちらかに決めて、そろえ続けられるようにする必要があった。

## 決定

- ファイル直下の関数（コンポーネントを含む。export するもの・しないもの、どちらも）は `function` で書く
- 関数の中で作る関数（イベントハンドラー、コールバックなど）と、オブジェクトの中の関数は、アロー関数でよい
- 関数式（`const f = function () {}`）は使わない
- ESLint（`func-style` と `no-restricted-syntax`）でチェックする

## 検討した案

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| A. ファイル直下は `function`、中はアロー関数でよい（採用） | Next.js のページ（default export）を 1 行で書ける。shadcn/ui が作る部品と書き方がそろう。補助の関数をファイルの下に置ける（巻き上げ） | 関数全体に型を 1 つ当てる書き方（`const f: Handler = ...`）ができない |
| B. ファイル直下も `export const` ＋アロー関数 | ほかの定数と見た目がそろう。関数全体に型を当てられる | ページは `const Page = ...` と `export default Page` の 2 行になる。shadcn/ui で部品を追加・上書きするたびに書き方がずれる。今のコードと資料の例をすべて書き換える必要がある |
| C. すべて `function`（関数の中のイベントハンドラーも） | 例外がない | `map` に渡す関数やイベントハンドラーまで `function` になり、かえって読みにくい |
| D. 決めない | 手間がない | ファイルごとに書き方がばらつく |

## 理由

- Next.js のページやレイアウトは default export が必須で、`function` なら `export default async function Page()` の 1 行で書ける
- shadcn/ui は部品を `function` で作る。B にすると、`pnpm shadcn:add` で追加・上書きするたびに書き直しが必要になる
- React と Next.js の公式ドキュメントも `function` で書いている
- B の一番の利点（関数全体に型を当てられる）が必要な場面は、今のところない。ページの props には Next.js が型（`PageProps`）を用意している
- 関数の中まで `function` にすると読みにくくなるので、ファイル直下だけに絞った

## 影響

- ファイル直下にアロー関数や関数式を書くと、`pnpm lint` でエラーになる
- 関数全体の型を当てたい場合（外部のライブラリがハンドラーの型を用意している場合など）は、引数と戻り値に型を付けて `function` で書く
- **見直す条件**: 関数全体に型を当てる書き方が必要な場面が増え、`function` で書くと型が冗長になる場合
