# ADR-013 AI 駆動開発の資料を `docs/05_AI駆動開発/` にまとめ、ルールの本体は `docs/` の 1 か所に保つ

| 項目 | 内容 |
| ---- | ---- |
| 状態 | 採用 |
| 日付 | 2026-09-26 |
| 決めた人 | |

## 背景

AI（Claude Code）を使った開発を進める中で、AI 用の仕組み（`AGENTS.md`、skill、hook）が増えてきた。一方で、「AI をどう使って開発するか」「AI の変更をどう確認するか」を人が読める資料がなかった。今後、skill・hook・補助の AI（agents）・外部サービスとのつなぎ込み（MCP）などで、この分野の資料は増える見込みがある。

また、Claude Code の設定の例として、`.claude/rules/` にルールを分けて置く構成もよく紹介されている。このプロジェクトでは、ルールの本体を `docs/` に置いているため、どう扱うかを決める必要があった。

## 決定

- AI を使った開発の進め方と仕組みの資料を、`docs/05_AI駆動開発/` にまとめる（[ADR-007](./ADR-007_資料の構成.md) の構成に 1 つ足す）
- アプリのコードのルールは、今までどおり 01・02 に書く。05 には「AI をどう使うか」だけを書き、01・02 の内容は写さずにリンクする
- ルールの本体は `docs/` の 1 か所に保つ。`.claude/rules/` は使わず、`.claude/` には skill と hook だけを置く

## 検討した案

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| A. `docs/05_AI駆動開発/` を作る（採用） | AI の資料がまとまって見つけやすい。増えても 02 のアプリの実装ルールと混ざらない | 資料の構成（ADR-007）に 1 つ足すことになる |
| B. `docs/02_共通設計/12_AI駆動開発.md` の 1 本にする | フォルダが増えない。02 には開発の進め方（Git、テスト、CI）もすでにある | 増えたときに 02 の中で AI の資料が並び、アプリの実装ルールと混ざる。後から移すとリンクの書き直しが必要 |
| C. `.claude/README.md` に書く | 設定のすぐ近くにある | 見えにくいフォルダの中なので、人が読まない |
| D. `AGENTS.md` に書き足す | 新しいファイルがいらない | 毎回 AI に読み込まれるので、長くなるほど無駄が増える。人向けの説明には向かない |

### ルールの置き場所について

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| `docs/` の 1 か所（採用） | 人も AI も同じものを読む。食い違わない | AI が読むときに、どの資料を読むかを案内する必要がある（AGENTS.md と skill で案内する） |
| `.claude/rules/` にも置く | 「このフォルダを触るときだけ読む」といった指定ができる | `docs/` と同じ内容を 2 か所に書くことになり、食い違う（docs/README の「同じ内容を 2 か所に書かない」に反する） |

## 理由

- この分野の資料は増える見込みがあり、最初からフォルダにしておく方が、後から移すより手間が少ない
- 番号は 05 にした。04 より前に入れると、ADR へのリンクをすべて書き直すことになるため
- ルールを 1 か所に保つ方針は、層の説明ページ（SCR-020）でコード例のずれをテストで止めたのと同じ考え方。写しを増やさない

## 影響

- `docs/README.md` の「読む順番」と「迷ったときの探し方」に 05 を足す
- `AGENTS.md` の「Claude Code の設定」から、05 へリンクする
- skill・hook を足したら、[02 仕組み](../05_AI駆動開発/02_仕組み.md) の一覧に書き足す
- **見直す条件**: 「特定のフォルダを触るときだけ読ませたいルール」が増え、AGENTS.md と skill の案内だけでは読み落としが目立つようになった場合（そのときは `.claude/rules/` に `docs/` へのリンクだけを置く形を検討する）
