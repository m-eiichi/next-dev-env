# ADR-004 共通コンポーネントを Atomic Design で分け、shadcn/ui は専用のスクリプトで追加する

| 項目 | 内容 |
| ---- | ---- |
| 状態 | 採用 |
| 日付 | 2026-09-23 |
| 決めた人 | |

## 背景

shadcn/ui の部品は、初期設定では `src/components/ui/button.tsx` のように 1 つのフォルダにまとめて置かれる。参考にした既存プロジェクト（benefit-fe）では、Atomic Design で `atoms/{名前}/index.tsx` の形に並べ替えていた。部品が増えたときの探しやすさと、既存プロジェクトとのそろえ方を決める必要があった。

## 決定

- 複数の画面で使うコンポーネントは `src/components/{atoms,molecules,organisms}/{名前}/index.tsx` に置く
- その画面だけで使うコンポーネントは `src/app/**/_components/{名前}.tsx` に置く
- shadcn/ui の部品は `pnpm shadcn:add <atoms|molecules> <名前>`（`scripts/shadcn-add.mjs`）で追加する。`pnpm shadcn add` は直接使わない
- `src/components/` のフォルダ名には `_` を付けない

## 検討した案

### 共通コンポーネントの分け方

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| A. Atomic Design（採用） | 部品の大きさで置き場所が決まり、増えても探しやすい。既存プロジェクトとそろう | shadcn/ui の初期設定と違うので、追加のスクリプトが必要。atoms か molecules か迷うことがある |
| B. shadcn/ui の初期設定（`components/ui/button.tsx`） | 公式のドキュメントや例とそのまま対応する。スクリプトがいらない | 部品が増えると 1 つのフォルダに並び、探しにくい |

### shadcn/ui の追加スクリプトで気をつけたこと

shadcn/ui の部品は、他の部品を `@/components/ui/button` のように import している。ファイルを移すだけでは import が壊れるため、スクリプトで移動先のパスに書き換える。依存として一緒に入った部品は atoms に置き、すでにある部品は手を入れている可能性があるので上書きしない（`--overwrite` を付けたときだけ置き換える）。

### `src/components/` に `_` を付けるか

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| `components`（採用） | shadcn/ui の初期設定（`@/components`）と同じ。ls-lint に例外がいらない | `_components` と名前の付け方がそろわない |
| `_components` | `src/app/**/_components` と名前がそろう | `src/app/` の外では `_` に意味がない（`_` がルーティングの対象外という意味を持つのは `src/app/` の中だけ）。shadcn/ui の設定と ls-lint の変更が必要 |

## 理由

- 既存プロジェクトとそろえ、部品が増えても探しやすくするため Atomic Design にした
- 「複数の画面で使うか」で `components/` と `_components/` を分け、名前だけで役割がわかるようにした

## 影響

- `components.json` の `aliases.ui` は初期値（`@/components/ui`）から変えない。スクリプトはここに作られたファイルを移すため
- `src/components/ui/` にファイルが残っていたら、追加が途中で失敗している
- 部品は最初 `_components/` に置き、2 つ目の画面で使うことになった時点で `src/components/` に移す
