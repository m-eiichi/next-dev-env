# ADR-017 未使用コードの検出（knip）を必須にし、わざと置いているものは設定で外す

| 項目 | 内容 |
| ---- | ---- |
| 状態 | 採用 |
| 日付 | 2026-09-26 |
| 決めた人 | |

[ADR-006](./ADR-006_CIとカバレッジ.md) の「未使用コードの検出（knip）は、開発の初期は参考にとどめ、指摘が 0 件になったら必須にする」を変える。ADR-006 のほかの決定（CI の通過をマージの条件にする、カバレッジの目標）はそのまま。

## 背景

ADR-006 では、knip を参考のみ（CI で失敗してもマージできる）にしていた。導入したがまだ使っていない依存（Font Awesome、React Hook Form）や、先に用意した部品（`badge` など）があり、knip がいつも失敗するためだった。

AI に実装させるようになって、次の問題が出た。

- knip がいつも失敗するので、AI は「今回の変更で生まれた、使っていないコード」と「わざと置いているもの」を見分けられない。新しい指摘を見落とすか、knip を通そうとして、わざと置いている部品や依存を消してしまうおそれがある
- 「今回のファイルの指摘だけ直す」と skill に書いても、毎回見比べる判断を AI に任せることになる。このプロジェクトでは、機械で判定できるものは機械で止める方針にしている（[05_AI駆動開発/02_仕組み](../05_AI駆動開発/02_仕組み.md) の「3.1」）
- 「0 件になったら必須にする」のままでは、わざと置いているものが残るかぎり、いつまでも必須にできない

## 決定

- わざと置いているものと、誤った指摘（`node` で直接実行するスクリプトなど）を `knip.json` で対象から外し、指摘を 0 件にする
- knip を、ほかのチェックと同じジョブ（`Lint / 型チェック / テスト / ビルド`）に入れて必須にする。手元で流す「CI と同じチェック」にも `pnpm knip` を足す
- `treatConfigHintsAsErrors: true` にし、外したものを使い始めたら knip が失敗して、設定から消すように促すようにする

外しているものと、knip が失敗したときにすることは [11 CI](../02_共通設計/11_CI.md) の「3.3」に書く。

## 検討した案

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| A. わざと置いているものを設定で外し、今すぐ必須にする（採用） | 「knip が通ったか」だけで判断できる。指摘が出たら、必ず今回の変更によるもの | 外したものを使い始めたときに、設定を直す手間がある（knip が教えてくれる） |
| B. 参考のままにし、「今回のファイルの指摘だけ直す」を skill に書く | 設定がいらない | 毎回の見比べを AI に任せることになり、見落としや消しすぎが起きる |
| C. まだ使っていない依存と部品を消して 0 件にする | 設定がいらない | 使うときに入れ直す必要がある。依存を消すのは人に確かめる作業で、用意した理由も失われる |

## 理由

- 機械で判定できるものは機械で止める方針に合う。AI にも人にも、判断の基準が「knip が通ったか」の 1 つになる
- `treatConfigHintsAsErrors` で、外したものを使い始めたときに knip が失敗するので、外したまま忘れる心配が小さい（使い始めると「Remove from ignoreDependencies」などと出ることを確かめた）
- 必須のチェックの名前を変えずに済むよう、同じジョブに入れた。GitHub のブランチ保護の設定を直す必要がない

## 影響

- `knip.json` に足すのは、「わざと置いている」と説明できるものだけにする。足したら [11 CI](../02_共通設計/11_CI.md) の「3.3」の表に理由を書く
- shadcn/ui で部品を足すと、使っていない export（`badgeVariants` など）が指摘されることがある。そのときは `ignoreIssues` にそのファイルを足す
- CI の時間が、knip の分（数秒〜十数秒）だけ延びる
