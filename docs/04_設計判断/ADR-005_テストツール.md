# ADR-005 テストに Vitest を使い、E2E は Playwright にする

| 項目 | 内容 |
| ---- | ---- |
| 状態 | 採用 |
| 日付 | 2026-09-23 |
| 決めた人 | |

## 背景

層を分けた構成（[ADR-001](./ADR-001_コードの層分け.md)）では、テストの中心は Next.js に依存しないドメイン層とユースケースになる。これを速く書いて実行できるツールを決める必要があった。

## 決定

| 種類 | ツール | 導入のタイミング |
| ---- | ------ | ---------------- |
| 単体テスト（ドメイン層、ユースケース） | Vitest | 最初から |
| コンポーネントのテスト | Vitest + React Testing Library | 必要になったら |
| E2E テスト（`async` の page、画面をまたぐ操作） | Playwright | 画面が増えてきたら |

## 検討した案

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| A. Vitest（採用） | 設定なしで TypeScript・ESM を扱え、速い。書き方は Jest とほぼ同じ。Next.js 公式の設定ガイドがある | `async` の Server Component はテストできない |
| B. Jest | 利用者が多く、情報が多い | TypeScript・ESM の設定に手間がかかる。遅め。`async` の Server Component はテストできない（A と同じ） |

## 理由

- テストの中心が素の TypeScript（ドメイン層・ユースケース）なので、速く動く単体テストのツールが合う
- `async` の Server Component をテストできないのは Jest も同じで、Next.js 公式も E2E テストを推奨している。この構成では表示部分を DTO を受け取る同期のコンポーネントに切り出せるため、大きな問題にならない

## 影響

- `server-only` は `vitest.config.ts` で空のモジュールに置き換える
- 実行環境は基本が `node`、コンポーネントだけ `jsdom`
- Server Action / Route Handler は原則テストしない（ユースケースを呼ぶだけのため）
