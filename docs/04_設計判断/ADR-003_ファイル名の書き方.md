# ADR-003 ファイル名・フォルダ名をすべて kebab-case にする

| 項目 | 内容 |
| ---- | ---- |
| 状態 | 採用 |
| 日付 | 2026-09-23 |
| 決めた人 | |

## 背景

ファイル名のルールを ls-lint でチェックするにあたり、コンポーネントのファイル名を PascalCase（`PostList.tsx`）にするか kebab-case（`post-list.tsx`）にするかを決める必要があった。

## 決定

- `src/` の下のファイル名・フォルダ名は、すべて kebab-case にする（コンポーネントも `post-list.tsx`）
- コンポーネント名（コードの中の名前）は PascalCase のまま（`export function PostList`）
- `src/app/` のフォルダだけは、Next.js の決まりの形（`[id]`、`(group)`、`_components`、`@slot`）も許可する

## 検討した案

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| A. すべて kebab-case（採用） | Next.js の決まった名前（`page.tsx`）や shadcn/ui のコンポーネント名（`dropdown-menu`）と書き方がそろう。ls-lint に例外がいらない。大文字・小文字だけの名前の変更によるトラブルが起きない | ファイル名とコンポーネント名が一致しない |
| B. コンポーネントだけ PascalCase | ファイル名とコンポーネント名が一致する。React 全般でよく使われる | Next.js・shadcn/ui のファイルと書き方が混ざる。ls-lint に例外が必要で、`src/app/` の中では両方を許可する緩いルールになる |

## 理由

- 書き方が 1 つにそろい、ルールが単純になる
- Mac のファイルシステムは大文字・小文字を区別しないため、`postList.tsx` → `PostList.tsx` のような変更を Git が検知しにくく、トラブルになりやすい。すべて小文字ならこれが起きない
- チームの好みとしても kebab-case にそろえたかった

## 影響

- `.ls-lint.yml` で CI でもチェックする
- 新しい種類の拡張子（例: `.schema.ts`）を使い始めるときは、`.ls-lint.yml` に追加する
