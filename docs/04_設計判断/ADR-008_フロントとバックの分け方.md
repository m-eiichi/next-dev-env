# ADR-008 バックを `src/server/` にまとめ、フロントとの入り口を `src/server/entry/` に絞る

| 項目 | 内容 |
| ---- | ---- |
| 状態 | 採用 |
| 日付 | 2026-09-23 |
| 決めた人 | |

## 背景

[ADR-002](./ADR-002_画面とサーバーのつなぎ方.md) で、画面からユースケースを Server Component / Server Action で直接呼ぶことにした。その結果、`page.tsx` の中で「画面の表示（プレゼンテーション層）」と「依存を組み立ててユースケースを呼ぶ（入口）」が混ざり、`src/app/` の中に Server Action（`actions.ts`）も置かれる形になっていた。

参考にした既存プロジェクト（RootLog）では、画面は API Route を `fetch` するだけだったため、`src/app/` をまとめてプレゼンテーション層として扱えた。このプロジェクトでは同じ線をフォルダでは引けておらず、画面の部品が DI コンテナやユースケースを import しても、フォルダを見ただけでは気付けなかった。

## 決定

- `src/server/` の外をフロント（`src/app/`、`src/components/`、`src/hooks/`）、中をバックとし、アプリケーション層・ドメイン層・インフラストラクチャ層を `src/server/` の下に移す
- 入口の中身を `src/server/entry/` に置く。取得の関数は `queries/`、Server Action は `actions/`、Route Handler の中身は `api/`
- フロントが `src/server/` から import してよいのは、`src/server/entry/` の関数と DTO の型だけにする。`page.tsx` は取得の関数を呼ぶだけ、`route.ts` は `src/server/entry/api/` から読み込むだけにする

[ADR-001](./ADR-001_コードの層分け.md) の層分けと、[ADR-002](./ADR-002_画面とサーバーのつなぎ方.md) の「API を挟まずにユースケースを呼ぶ」方針は変えない。変えるのは、依存を組み立てる場所（Server Component / Server Action / Route Handler の中 → `src/server/entry/`）と、各層のフォルダの位置だけ。

## 検討した案

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| A. バックを `src/server/` にまとめ、入口を `src/server/entry/` に置く（採用） | `src/server/` の外と中で、フロントとバックが一目でわかる。ESLint で「フロントは `src/server/entry/` と DTO の型だけ import してよい」とチェックしやすい | import のパスが 1 段長くなる（`@/server/domain/...`）。取得 1 つにつきファイルが 1 つ増える |
| B. `src/entry/` を作り、各層と並べて置く（`src/entry/`、`src/application/` などが同じ階層） | 資料の層の一覧とフォルダが 1 対 1 で対応する。パスが短い | フォルダの一覧を見ても、どこからがバックかわからない |
| C. フォルダは変えず、ルールで分ける（`page.tsx` と `actions.ts` を入口として扱う） | ファイルが増えない。Server Action を画面のそばに置ける | 1 つのファイルに表示と組み立てが混ざる。フォルダの境目がないので、ESLint でチェックしにくい |
| D. 機能ごとに分ける（`src/features/post/{ui,server}/`） | 1 つの機能のファイルが 1 か所に集まる | 層分け（ADR-001）と Atomic Design（ADR-004）を両方作り直すことになり、変更が大きい |

## 理由

- フロントとバックの境目をフォルダではっきりさせたかった。A は境目が `src/server/` の 1 か所だけなので、人も ESLint も判断しやすい
- 各層のフォルダの中身がまだ空のうちに移すので、移す手間がほとんどない
- 取得の関数が増える分のファイルは、`page.tsx` から組み立てがなくなることと、同じ取得を複数の画面で使い回せることで釣り合う

## 影響

- `src/app/` に Server Action（`actions.ts`）を置かない。1 画面だけで使うものも `src/server/entry/actions/` に置く
- `page.tsx` でユースケースを組み立てない。`'use cache'` などのキャッシュの指定も、取得の関数に書く
- `route.ts` はルートの設定（`export const dynamic` など）を除き、`src/server/entry/api/` から読み込むだけにする
- ESLint の `no-restricted-imports` で、フロントから `src/server/entry/` 以外（DTO の型を除く）を import できないようにする
- カバレッジの対象（[ADR-006](./ADR-006_CIとカバレッジ.md)）は、`src/server/domain/` と `src/server/application/` になる
- **見直す条件**: 取得の関数がユースケースを呼ぶだけの薄いファイルばかりになり、ファイルが増えることの負担が大きくなった場合。または、バックを別のサーバーに分けることになった場合（そのときは `src/server/` をそのまま切り出せる）
