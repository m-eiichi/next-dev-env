# ADR-012 Cache Components を使い、キャッシュは `'use cache'` で指定する

| 項目 | 内容 |
| ---- | ---- |
| 状態 | 採用 |
| 日付 | 2026-09-25 |
| 決めた人 | |

## 背景

[02 システム構成](../01_全体設計/02_システム構成.md) の「5. レンダリング・キャッシュの方針」で、Cache Components（`cacheComponents`）を使うかどうかが決まっていなかった。一方で、[04 データ取得・更新](../02_共通設計/04_データ取得・更新.md) の「2. キャッシュ」は `'use cache'` を前提に書かれていた。`'use cache'` は Cache Components を有効にしないと使えないため、資料と設定が食い違っていた。

DB（Neon など）を使い始めると、「ビルド時に 1 回だけ読み、次のデプロイまで古いまま」にならないよう、キャッシュの方式を決める必要がある。

## 決定

- `next.config.ts` で `cacheComponents: true` にする
- キャッシュは、取得の関数（`src/server/entry/queries/`）に `'use cache'`、`cacheLife`、`cacheTag` で指定する（[ADR-008](./ADR-008_フロントとバックの分け方.md) で決めた置き場所）
- キャッシュしない取得は、`<Suspense>` で囲んでアクセスのたびに取得する

## 検討した案

| 案 | 良い点 | 悪い点 |
| -- | ------ | ------ |
| A. Cache Components を使う（採用） | 関数・部品の単位でキャッシュを指定できる。1 つのページの中で、静的な部分と動的な部分を分けられる（Partial Prerendering）。Next.js が進めている方向。04 の資料をそのまま使える | ページの設定の `revalidate`・`dynamic`・`dynamicParams` が使えなくなる。ビルド時の制約が厳しい（現在時刻などを読むとエラーになる） |
| B. 使わない（`revalidate`・`unstable_cache`） | 今までの Next.js の書き方で、情報が多い | ページ単位の指定が中心で、1 つのページの中で分けにくい。`unstable_cache` は将来変わる可能性がある。04 の資料を書き直す必要がある |
| C. TanStack Query でブラウザ側で取り直す | サーバーの設定を変えなくてよい | サーバーで作るページは古いまま。訪問者ごとに DB を読む。表示が入れ替わる。[ADR-002](./ADR-002_画面とサーバーのつなぎ方.md) の「TanStack Query は取り直しが必要な場合だけ」にも合わない |

## 理由

- キャッシュの指定を取得の関数に書く、という ADR-008 の決定と、関数単位で指定できる `'use cache'` がよく合う
- 入口は DTO（ただのオブジェクト）を返すので、「戻り値はシリアライズできるものだけ」という `'use cache'` の制約をそのまま満たす
- まだページが少なく、有効にしても直す箇所が少ない（今回直したのは 1 か所だけ。下の「影響」）

## 影響

- ページやルートの設定で `revalidate`・`dynamic`・`dynamicParams` を使わない。[SCR-020](../03_画面設計/SCR-020_層の説明.md) は、これを見越して `dynamicParams` を使わずに作ってある
- キャッシュしない取得（DB など）は、取得する部品を `<Suspense>` で囲む。囲まないとビルドでエラーになる
- `'use cache'` の中では `cookies()`・`headers()`・`searchParams` を使えない。ログイン中のユーザーを調べる取得は、外で読んだ値を引数で渡すか、`'use cache: private'` を使う
- TanStack Query で `initialData` を渡す Client Component は、`<Suspense>` で囲む（TanStack Query が現在時刻を読み、ビルドでエラーになるため）。囲んだ部分はブラウザで描かれ、HTML には `fallback` が入る。SCR-011 で対応した
- 画面を移動しても、前の画面の状態が保たれる（React の `<Activity>`）。入力中の内容などが残る
- 標準のキャッシュはサーバーのメモリに置く。サーバーレスでは、アクセスをまたいで引き継がれないことがある
- **見直す条件**: Cache Components の制約のために、書き方が大きく複雑になる場面が増えた場合
