## 1. 概要

### 1.1 目的

**アプリの機能ではなく、実装の見本**。題材は「メモ」（タイトルと本文）。更新（command）側の見本にする。フォームの入力 → Server Action → ユースケース → エンティティ・リポジトリ、の流れと、業務のルール（タイトルの重複禁止など）の守り方、登録後にキャッシュを更新して一覧（SCR-010）に反映させる方法を、実際に動くコードで見られるようにする（[ADR-016](../04_設計判断/ADR-016_CQRS.md)）。

## 5. 入力項目

| No | 項目名 | name 属性 | 種類 | 必須 | 初期値 | バリデーション | エラーメッセージ |
| -- | ------ | --------- | ---- | ---- | ------ | -------------- | ---------------- |
| 1 | タイトル | `title` | text | 必須 | 空 | 前後の空白を除いて 1〜100 文字 | タイトルを入力してください / タイトルは 100 文字以内で入力してください |
| 2 | 本文 | `body` | textarea | 任意 | 空 | 200 文字以内 | 本文は 200 文字以内で入力してください |

- バリデーションは、クライアント（`required`、`maxLength`）と、サーバー（Server Action の中の Zod）の両方で行う
- 文字数のルールは、ドメイン層（値オブジェクト・エンティティ）を正とする。Zod は画面にエラーを出すための形式のチェック（[06 アーキテクチャ](../01_全体設計/06_アーキテクチャ.md) の「4.4」の「Zod とドメインのチェックの違い」）

### 5.1 業務のルール（ドメイン層・ユースケース）

| ルール | 守る場所 | 違反したとき |
| ------ | -------- | ------------ |
| タイトルは前後の空白を除いて 1〜100 文字 | 値オブジェクト `NoteTitle`（今ある） | `DomainError` |
| 本文は 200 文字以内。空白だけなら「本文なし」（`null`） | エンティティ `Note.create()` | `DomainError` |
| 同じタイトルのメモは登録できない（前後の空白を除いて比べる） | ユースケース（リポジトリの `existsByTitle()` で確かめる） | 重複のエラー（`DomainError` を継承）→「同じタイトルのメモがすでにあります」 |

## 7. データ取得・更新

### 7.1 取得

なし

### 7.2 更新

| No | 処理 | 方式 | 入力 | 出力 | 更新後にすること |
| -- | ---- | ---- | ---- | ---- | ---------------- |
| 1 | メモを登録する | Server Action `createNote`（`src/server/entry/actions/note/create-note.ts`） | `FormData`（`title`、`body`） | `ActionResult<NoteDto>`（成功したら移動するので、画面が受け取るのは失敗のときだけ） | `updateTag("notes")`（一覧の取得の関数のキャッシュを捨てる）→ `redirect("/notes")` |

- `revalidateTag` ではなく `updateTag` を使う。`updateTag` は Server Action の中だけで使え、次のアクセスで新しいデータができるまで待つので、登録した人に古い一覧を見せない（[04 データ取得・更新](../02_共通設計/04_データ取得・更新.md) の「3」）
- 登録したデータは、メモリ上の仮のリポジトリに入る。**サーバーを立ち上げ直すと消える。サーバーレスの環境では、アクセスをまたいで残らないことがある**。DB が決まるまでの見本として割り切る
