## 1. 概要

### 1.1 目的

フロント → 入口 → ユースケース → ドメイン → インフラストラクチャの流れ（[06 アーキテクチャ](../01_全体設計/06_アーキテクチャ.md)）を、実際に動くコードで見られるようにする。新しい画面を作るときの見本にする。DB はまだ決まっていないので、データはメモリ上の仮のリポジトリから返す。

### 1.2 ルーティング

| 項目 | 内容 |
| ---- | ---- |
| URL パス | `/example` |
| 実装ファイル | `src/app/example/page.tsx` |
| レイアウト | `src/app/layout.tsx` |
| 動的パラメータ (`params`) | なし |
| クエリ (`searchParams`) | なし |

### 1.3 アクセス権限

| 項目 | 内容 |
| ---- | ---- |
| 閲覧できるユーザー | 全員 |
| 権限がない場合 | なし |
| チェックする場所 | なし（認証がまだないため、ユースケースでも認証チェックをしない） |

### 1.4 メタデータ

| 項目 | 内容 |
| ---- | ---- |
| title | `サンプル一覧`（ルートレイアウトの `title.template` で `サンプル一覧 \| Next.js 開発テンプレート` になる） |
| description | ルートレイアウトの `description` |
| 生成方法 | `metadata` を静的に書く |
| OGP / robots | なし |

## 2. 画面レイアウト

```
+--------------------------------------+
| Header（共通）                         |
+--------------------------------------+
| [A] 見出しと説明文                      |
| [B] サンプルの一覧（カード）              |
| [C] トップへ戻るリンク                   |
+--------------------------------------+
| Footer（共通）                         |
+--------------------------------------+
```

### 2.1 レスポンシブ

| ブレークポイント | レイアウトの違い |
| ---------------- | ---------------- |
| モバイル (< `sm`) | [B] は 1 列 |
| `sm` 以上 | [B] は 2 列 |
