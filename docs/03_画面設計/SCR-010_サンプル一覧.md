## 1. 概要

### 1.1 目的

フロント → 入口 → ユースケース → ドメイン → インフラストラクチャの流れ（[06 アーキテクチャ](../01_全体設計/06_アーキテクチャ.md)）を、実際に動くコードで見られるようにする。新しい画面を作るときの見本にする。DB はまだ決まっていないので、データはメモリ上の仮のリポジトリから返す。

### 1.2 ルーティング

| 項目 | 内容 |
| ---- | ---- |
| URL パス | `/example` |
| 実装ファイル | `src/app/example/page.tsx` |
| レイアウト | `src/app/layout.tsx` |
| 動的パラメータ (`params`) | なし |
| クエリ (`searchParams`) | なし |

### 1.3 アクセス権限

| 項目 | 内容 |
| ---- | ---- |
| 閲覧できるユーザー | 全員 |
| 権限がない場合 | なし |
| チェックする場所 | なし（認証がまだないため、ユースケースでも認証チェックをしない） |

### 1.4 メタデータ

| 項目 | 内容 |
| ---- | ---- |
| title | `サンプル一覧`（ルートレイアウトの `title.template` で `サンプル一覧 \| Next.js 開発テンプレート` になる） |
| description | ルートレイアウトの `description` |
| 生成方法 | `metadata` を静的に書く |
| OGP / robots | なし |

## 2. 画面レイアウト

```
+--------------------------------------+
| Header（共通）                         |
+--------------------------------------+
| [A] 見出しと説明文                      |
| [B] サンプルの一覧（カード）              |
| [C] 登録・検索のサンプルへのリンク、トップへ戻るリンク |
+--------------------------------------+
| Footer（共通）                         |
+--------------------------------------+
```

### 2.1 レスポンシブ

| ブレークポイント | レイアウトの違い |
| ---------------- | ---------------- |
| モバイル (< `sm`) | [B] は 1 列 |
| `sm` 以上 | [B] は 2 列 |

## 3. コンポーネント構成

| 記号 | コンポーネント | ファイル | 種別 | 備考 |
| ---- | -------------- | -------- | ---- | ---- |
| - | Page | `src/app/example/page.tsx` | Server | 取得の関数 `listExamples` を呼び、結果を [B] に渡すだけ |
| A | （Page に直接書く） | `src/app/example/page.tsx` | Server | |
| B | ExampleList | `src/app/example/_components/example-list.tsx` | Server | `ExampleDto[]` を受け取って表示するだけ。SCR-011 でも使う |
| C | （Page に直接書く） | `src/app/example/page.tsx` | Server | `next/link` |

- 操作がないので、Client Component は使わない

### 3.1 バック側のファイル

| 層 | ファイル | 役割 |
| -- | -------- | ---- |
読み取り（query）側。ドメイン層は通らない（[ADR-016](../04_設計判断/ADR-016_CQRS.md)）。更新（command）側のファイルは [SCR-012](./SCR-012_サンプル登録.md) の「3.1」。

| 層 | ファイル | 役割 |
| -- | -------- | ---- |
| 入口 | `src/server/entry/queries/example/list-examples.ts` | 依存を組み立て、クエリを呼ぶ。`'use cache'`・`cacheLife("max")`・`cacheTag("examples")` を付ける |
| アプリケーション層 | `src/server/application/query/example/list-examples.query.ts` | Query Service を呼び、DTO を返す（検索語も受け取れる。SCR-011 と共用） |
| アプリケーション層 | `src/server/application/query/example/example-query-service.ts` | Query Service のインターフェース（DTO を返す） |
| アプリケーション層 | `src/server/application/dto/example/example.dto.ts` | `ExampleDto` |
| インフラストラクチャ層 | `src/server/infrastructure/in-memory/example/` | Query Service の実装。登録（SCR-012）のリポジトリと、同じメモリ上のデータを共有する |
| インフラストラクチャ層 | `src/server/infrastructure/di/container.ts` | DI コンテナ |

## 7. データ取得・更新

### 7.1 取得

| No | 取得するデータ | 取得元 | 実行する場所 | キャッシュ | 再検証 |
| -- | -------------- | ------ | ------------ | ---------- | ------ |
| 1 | サンプルの一覧 | メモリ上の仮のデータ（Query Service） | 取得の関数 `listExamples`（Server Component から呼ぶ） | `'use cache'`・`cacheLife("max")`・`cacheTag("examples")`。ビルド時に作り、登録されるまで使い回す | 登録（SCR-012）の Server Action で `updateTag("examples")` |

- データが変わるのは登録のときだけなので、時間では作り直さず（`max`）、登録のときにタグで捨てる
