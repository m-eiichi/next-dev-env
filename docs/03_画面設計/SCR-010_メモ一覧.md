## 1. 概要

### 1.1 目的

**アプリの機能ではなく、実装の見本**。題材は「メモ」（タイトルと本文）。読み取り（query）の流れ（画面 → 取得の関数 → クエリ → Query Service。[06 アーキテクチャ](../01_全体設計/06_アーキテクチャ.md) の「4.3」）とキャッシュの付け方を、実際に動くコードで見られるようにする。新しい一覧画面を作るときに真似する。DB はまだ決まっていないので、データはメモリ上の仮のデータ置き場から返す。

### 3.1 バック側のファイル

| 層 | ファイル | 役割 |
| -- | -------- | ---- |
読み取り（query）側。ドメイン層は通らない（[ADR-016](../04_設計判断/ADR-016_CQRS.md)）。更新（command）側のファイルは [SCR-012](./SCR-012_メモ登録.md) の「3.1」。

| 層 | ファイル | 役割 |
| -- | -------- | ---- |
| 入口 | `src/server/entry/queries/note/list-notes.ts` | 依存を組み立て、クエリを呼ぶ。`'use cache'`・`cacheLife("max")`・`cacheTag("notes")` を付ける |
| アプリケーション層 | `src/server/application/query/note/list-notes.query.ts` | Query Service を呼び、DTO を返す（検索語も受け取れる。SCR-011 と共用） |

| インフラストラクチャ層 | `src/server/infrastructure/in-memory/note/` | Query Service の実装。登録（SCR-012）のリポジトリと、同じメモリ上のデータを共有する |

## 7. データ取得・更新

### 7.1 取得

| No | 取得するデータ | 取得元 | 実行する場所 | キャッシュ | 再検証 |

| 1 | メモの一覧 | メモリ上の仮のデータ（Query Service） | 取得の関数 `listNotes`（Server Component から呼ぶ） | `'use cache'`・`cacheLife("max")`・`cacheTag("notes")`。ビルド時に作り、登録されるまで使い回す | 登録（SCR-012）の Server Action で `updateTag("notes")` |
