## 5. 入力項目

| No | 項目名 | name 属性 | 種類 | 必須 | 初期値 | バリデーション | エラーメッセージ |
| -- | ------ | --------- | ---- | ---- | ------ | -------------- | ---------------- |
| 1 | 検索語 | `q` | search | 任意 | 空 | 最大 100 文字 | 検索語は 100 文字以内で入力してください |

- クライアントでは `maxLength` で 100 文字を超えて入力できないようにする。サーバー（入口）でも Zod でチェックする
- 前後の空白は無視する。空なら全件を表示する
- 検索語はタイトルと説明の部分一致（大文字・小文字を区別しない）

## 6. 操作・イベント

| No | きっかけ | 処理内容 | 成功したとき | 失敗したとき |
| -- | -------- | -------- | ------------ | ------------ |
| 1 | 画面を開く | 一覧を取得（Server Component） | 全件を表示 | Next.js の既定のエラー画面 |
| 2 | 検索欄に入力する | 入力が 300 ミリ秒止まったら `GET /api/internal/examples?q=...` | 結果を表示。取得中は前の結果を表示したまま「検索中…」を出す | [C] にエラーメッセージを表示 |
| 3 | [サンプル一覧へ戻る] を押す | 画面を移動 | SCR-010 を表示 | - |

## 7. データ取得・更新

### 7.1 取得

| No | 取得するデータ | 取得元 | 実行する場所 | キャッシュ | 再検証 |
| -- | -------------- | ------ | ------------ | ---------- | ------ |
| 1 | 全件（初期表示） | メモリ上の仮のデータ（Query Service） | 取得の関数 `listExamples`（Server Component から呼ぶ） | SCR-010 と同じ（`cacheTag("examples")`） | 登録（SCR-012）で `updateTag("examples")` |
| 2 | 検索結果 | 同上 | Client Component の `useQuery` → `GET /api/internal/examples` | TanStack Query のキャッシュ。キーは `["examples", { keyword }]`、`staleTime` は 60 秒（`providers.tsx` の初期値） | なし |

- 検索語が空のときは、No.1 の結果を `initialData` として使い、ブラウザからは取得しない
- HTML には `fallback`（全件の一覧）が入る。検索欄と TanStack Query の部分はサーバーでは描かず、JavaScript が読み込まれた後にブラウザで描いて入れ替える（Next.js がクライアント側での描画に切り替える）。JavaScript が動かない環境では検索欄は出ないが、検索自体が JavaScript 前提なので問題にしない
