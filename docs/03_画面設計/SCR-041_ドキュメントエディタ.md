## 1. 概要

### 1.1 目的

**アプリの機能ではなく、実装の見本**。お絵描きツールのように、A4 の用紙にテキスト・四角形・線を置いて、ドキュメント（請求書など）のレイアウトを作る。メモ・TODO では見せていない、次のことを実際に動くコードで見られるようにする（役割分担は [03_画面設計/README](./README.md) の「実装の見本」）。

- 保存するまでの編集を、ブラウザ側の state だけで持つ大きめの Client Component（ドラッグ、元に戻す、キーボード操作）
- 画面の計算（描く・動かす・大きさを変える）を純粋な関数に分けて、テストする（`report-geometry.ts`）
- 入れ子の構造（部品の配列）を Server Action に関数として渡し、Zod（形）とドメイン層（ルール）の両方でチェックする
- 印刷（`print:` のクラスと `@page`）

画面の表記は「ドキュメント」、URL（`/reports`）とコード上の名前（`report`）は英語の `report` のままにしている。コードで `document` を使うと、ブラウザの `document`（DOM）と紛らわしいため。

### 1.2 ルーティング

| 項目 | 内容 |
| ---- | ---- |
| URL パス | `/reports/[id]` |
| 実装ファイル | `src/app/reports/[id]/page.tsx` |
| レイアウト | `src/app/layout.tsx` |
| 動的パラメータ (`params`) | `id`: string。ドキュメントの ID |
| クエリ (`searchParams`) | なし |

- `generateStaticParams` は使わない（ドキュメントはあとから作られるので、ビルドのときに ID がわからない）。`params` を読む部分は `<Suspense>` で囲む（SCR-031 と同じ）

| 項目 | 内容 |
| ---- | ---- |
| 閲覧できるユーザー | 全員 |
| 権限がない場合 | なし |
| チェックする場所 | なし（認証がまだないため） |

## 5. 入力項目

部品の種類ごとに、[E] で次を変えられる。長さの単位は mm、文字の大きさは pt。

| 部品 | 項目 |
| ---- | ---- |
| テキスト | 文字、大きさ、揃え（左・中央・右）、太字、X、Y、幅、高さ |
| 四角形 | X、Y、幅、高さ、線の太さ、塗り（なし・灰色） |
| 線 | 始点 X・Y、終点 X・Y、線の太さ |

- 画面の側では、用紙からはみ出さないように先に収める（`fitToPaper`）。最終的なルールのチェックはドメイン層（「5.1」）
- 文字の `{{項目名}}` は、差し込み項目の目印として書くだけ（差し込みの機能はない。「9. 未決事項」）

### 5.1 業務のルール（ドメイン層）

| ルール | 守る場所 | 違反したとき |
| ------ | -------- | ------------ |
| 名前は前後の空白を除いて 1〜50 文字 | 値オブジェクト `ReportName` | `DomainError` |
| 部品は 200 個まで | 値オブジェクト `ReportLayout` | `DomainError`「部品は 200 個までにしてください」 |
| 部品の ID は重ならない | 同上 | `DomainError`「部品の ID が重なっています」 |
| テキスト・四角形は用紙からはみ出さない。幅と高さは 1mm 以上 | 同上 | `DomainError` |
| 線の両端は用紙の中。長さ 0 の線は置けない | 同上 | `DomainError` |
| テキストは 200 文字まで。文字の大きさは 6〜72pt | 同上 | `DomainError` |
| 線の太さは 0.1〜3mm | 同上 | `DomainError` |
| レイアウトはルールを守るメソッドでだけ置き換える。違反したら元のまま | エンティティ `Report.replaceLayout()` | `DomainError` |
| 操作するドキュメントが存在すること | ユースケース（リポジトリの `findById()` で確かめる） | `ReportNotFoundError`「ドキュメントが見つかりません」 |

| 3 | [選択] で部品を押してドラッグする | 部品を動かす。用紙の端で止まる | - | - |
| 4 | 選んだ部品のつまみをドラッグする | テキスト・四角形は右下で大きさを変える。線は両端を動かす | - | - |
| 5 | 何もないところを押す | 選択を外す | - | - |
| 6 | [E] の欄を変える | 選んだ部品を変える | - | - |
| 7 | [前面へ] / [背面へ] / [複製] / [削除] を押す | 部品の並びを変える | - | - |
| 8 | [元に戻す] を押す | 1 つ前の部品の並びに戻す（50 回まで） | - | - |

| 10 | [印刷] を押す | `window.print()`。保存していない変更も含めて、用紙だけを印刷する | - | - |
| 11 | 保存していない変更があるまま、ページを離れる | ブラウザの確認を出す（`beforeunload`） | - | - |

## 7. データ取得・更新

### 7.1 取得

| No | 取得するデータ | 取得元 | 実行する場所 | キャッシュ | 再検証 |
| -- | -------------- | ------ | ------------ | ---------- | ------ |
| 1 | ドキュメント 1 件（部品をすべて含む） | メモリ上の仮のデータ（Query Service） | 取得の関数 `getReport(id)`（`<Suspense>` の中の Server Component から呼ぶ） | `'use cache'`・`cacheLife("max")`・`cacheTag("reports")`。`id` ごとに別に保存される | 作成・保存の Server Action で `updateTag("reports")` |

### 7.2 更新

| No | 処理 | 方式 | 入力 | 出力 | 更新後にすること |
| -- | ---- | ---- | ---- | ---- | ---------------- |
| 1 | レイアウトの保存 | Server Action `saveReportLayout` | `{ id, elements }`（部品の配列を丸ごと） | `ActionResult<ReportDto>` | `updateTag("reports")` |

- 部品を 1 つ動かすたびには保存しない。[保存] で部品の配列を丸ごと送り、置き換える
- フォームではなく、`startTransition` の中で Server Action を関数として呼ぶ（入力が入れ子の配列なので `FormData` にしない）
- 保存したデータはメモリ上の仮のデータ置き場に入る。サーバーを立ち上げ直すと消える（メモ・TODO と同じ割り切り）
