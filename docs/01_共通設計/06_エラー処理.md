# 06 エラー処理

## 1. エラーの種類と扱い

| 種類 | 例 | 扱い |
| ---- | -- | ---- |
| 入力エラー | バリデーション違反 | 例外にせず、Server Action の戻り値で返す（[05 フォーム・バリデーション](./05_フォーム・バリデーション.md)） |
| 見つからない | 存在しない ID | `notFound()` → `not-found.tsx` |
| 未認証・権限なし | | [01 認証・認可](./01_認証・認可.md) を参照 |
| 想定内の業務エラー | 在庫切れ、重複登録 | 戻り値で返し、画面にメッセージを出す |
| 想定外のエラー | DB の障害、バグ | 例外のまま投げ、`error.tsx` で受ける。ログに記録する |

- 想定内のエラーは戻り値で扱い、`throw` するのは想定外のものだけにする

## 2. エラー画面

| ファイル | 捕まえる範囲 | 表示内容 |
| -------- | ------------ | -------- |
| `src/app/error.tsx` | ルートレイアウトより下の全画面 | エラーメッセージ、再試行ボタン、トップへのリンク |
| `src/app/global-error.tsx` | ルートレイアウト自体のエラー | 簡素なエラー画面（`<html>` と `<body>` から自分で書く） |
| `src/app/not-found.tsx` | `notFound()` と存在しない URL | 404 のメッセージ、トップへのリンク |
| 各セグメントの `error.tsx` | そのセグメント以下 | 必要な画面だけに置く |

- `error.tsx` には `'use client'` が必要
- Next.js 16.3 の `error.tsx` は props で `error` と `retry` を受け取る。再試行ボタンには `retry()` を使う（`reset()` はデータを再取得しないため、基本は使わない）
- 本番環境では Server Component で発生したエラーの詳細は Client に届かず、`error.digest` だけが渡る。問い合わせの際に照合できるよう、`digest` を画面に表示するかどうか決める

## 3. エラーメッセージ

| 状況 | メッセージ |
| ---- | ---------- |
| 想定外のエラー | `エラーが発生しました。時間をおいて再度お試しください。` |
| 通信エラー | |
| 404 | `お探しのページは見つかりませんでした。` |
| 403 | `このページを表示する権限がありません。` |

- 画面には技術的な詳細（スタックトレース、SQL など）を出さない
