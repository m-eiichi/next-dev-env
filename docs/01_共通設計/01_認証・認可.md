## 3. チェックする場所

認可のチェックは 1 か所だけに頼らず、次の役割分担で行う。

| 場所 | 役割 | 注意点 |
| ---- | ---- | ------ |
| `src/proxy.ts` | Cookie の有無だけを見て、ログイン画面へ早めにリダイレクトする | 軽い確認だけにする。DB へのアクセスはしない |
| データアクセス層（例: `src/lib/dal.ts`） | セッションを検証し、ユーザー情報を返す関数を 1 か所にまとめる | ここを正とし、page や Server Action から呼ぶ |
| page / layout（Server Component） | 表示してよいかを判定する | layout のチェックだけでは子の page を守れない（layout は画面遷移のたびに再実行されないため） |
| Server Action / Route Handler | 実行してよいかを判定する | 外から直接呼び出せるので、**必ず**ここでもチェックする |

## 4. 権限がないときの動き

| 状況 | 動き | 実装 |
| ---- | ---- | ---- |
| 未ログインで保護された画面を開いた | ログイン画面へ移動し、ログイン後に元の画面へ戻す | `redirect('/login?next=...')` |
| ログイン済みだが権限がない | 403 画面を表示する | `forbidden()`（experimental）/ `notFound()` で存在を隠す |
| セッションの期限切れ | ログイン画面へ移動する | |

> `unauthorized()` / `forbidden()` を使う場合は、`next.config.ts` に `experimental.authInterrupts: true` を設定する。
