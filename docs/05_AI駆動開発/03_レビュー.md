# 03 レビュー

AI の変更を確認するときの観点。CI が通っていても、次の点は人の目で確かめる。

## 1. 確認すること

| 観点 | 確かめること |
| ---- | ------------ |
| 資料との食い違い | 資料が先に更新されているか。コードと資料の内容が合っているか。方針を変えたなら ADR があるか |
| 報告の「確かめていないこと」 | ブラウザでの見た目など、AI が確かめられなかったことを、人が確かめたか |
| テストの中身 | 実装をそのまま写しただけの期待値になっていないか。失敗するべき場合（ルール違反、0 件など）も試しているか |
| ルールを弱めていないか | `eslint-disable`、`@ts-ignore`、テストの削除・`skip`、カバレッジの対象の変更がないか |
| 頼んでいない変更 | 依頼と関係ないファイルが変わっていないか |
| 残り物 | 確認のための一時的なファイル（比較用のコピーなど）や、デバッグ用の出力が残っていないか |
| 依存 | `package.json` と `pnpm-lock.yaml` の変更に、理由の説明があるか |
| 秘密情報 | API キーや `.env.local` の値が、コード・資料・ログに入っていないか |
| テストやビルドで動くコード | テスト・スクリプト・設定ファイルが、外部との通信、リポジトリの外への書き込み、秘密の情報の読み込みや出力（`.env*` を開く、`process.env` を丸ごと出すなど）をしていないか。`pnpm test` などは確認なしで動くうえ、権限の設定ではコードの中身までは止められないため（[02 仕組み](./02_仕組み.md) の「2.3」） |
| AI の縛りの変更 | `.claude/`（skill とその中のスクリプト、hook、`settings.json`）、`AGENTS.md`、`CLAUDE.md`、`docs/05_AI駆動開発/` の差分で、AI の縛りが緩んでいないか。`deny` / `ask` の削除、`allow` の追加、「確認しない」「任せてよい」方向の書き換えなど。`docs/05_AI駆動開発/` は確認なしで編集できるため |

## 2. 探し方の例

```bash
# ルールを弱めていないか
git diff main -- src | grep -n -E "eslint-disable|@ts-ignore|@ts-expect-error|\.skip\(|\.only\("

# 変わったファイルの一覧（頼んでいない変更・残り物がないか）
git diff main --stat
git status --short

# テストやスクリプトが、通信・書き込み・秘密の情報の読み込みをしていないか
git diff main -- src scripts .claude '*.config.*' | grep -n -E "fetch\(|https?://|child_process|writeFile|readFile|\.env|process\.env"

# AI の縛りが変わっていないか（差分があれば中身を読む）
git diff main --stat -- .claude AGENTS.md CLAUDE.md docs/05_AI駆動開発
```
