# 02 仕組み

## 1. AI が読むもの

```
CLAUDE.md   → 「@AGENTS.md」（AGENTS.md を読み込む）と、Claude Code だけの仕組み（skill、hook）の案内
AGENTS.md   → 毎回読み込まれる入口。毎回守ることと、作業ごとに読む資料（docs/ の節）の目次
docs/       → ルールの本体。作業に関係する資料を、その都度読む
.claude/    → skill（必要なときに読み込む手順書）と hook（自動で動く処理）
```

| ファイル | 読まれるタイミング | 書くこと | 書かないこと |
| -------- | ------------------ | -------- | ------------ |
| `CLAUDE.md`（Claude Code が読む） | 毎回 | 先頭の `@AGENTS.md` と、Claude Code だけの仕組み（skill、hook）の案内 | どの AI にも共通のルール（Claude Code 以外の AI ツールは AGENTS.md を読むので、AGENTS.md に書く） |
| `AGENTS.md`（多くの AI ツールが読む） | 毎回 | どの AI にも共通の、機械では止められず毎回守ってほしいこと、作業ごとに読む資料の目次、作業を終える前のチェック | ルールの中身の要約（`docs/` の写しになる）。ESLint などが止めるルール（「1.1」） |
| `docs/` | 作業に関係するとき | ルールの本体、理由（ADR） | - |
| `node_modules/next/dist/docs/` | Next.js の機能を使うとき | （Next.js の公式の資料。このバージョンの正しい書き方） | - |

- AGENTS.md の先頭の Next.js についての段落は、`next dev` が書き足すもの。消しても元に戻るので、そのまま残す
- この 2 つの組み合わせ（AGENTS.md と、それを読み込む CLAUDE.md）は、Next.js が作る形と同じ（`node_modules/next/dist/server/lib/generate-agent-files.js`）。CLAUDE.md を消すと Claude Code がルールを読まなくなり、`next dev` も作り直さないので、消さない

### 1.1 読ませ方（Progressive Disclosure）

AI に最初から全部を読ませず、**作業に必要になった分だけを、段階的に読ませる**（[ADR-014](../04_設計判断/ADR-014_段階的に読ませる.md)）。毎回読まれるものを小さく保つほど、作業に関係する資料に注意を向けられる。

| 段階 | 読まれるタイミング | 置くもの | 置かないもの |
| ---- | ------------------ | -------- | ------------ |
| 1. 入口 | 毎回 | `CLAUDE.md`・`AGENTS.md`、skill の説明文（`description`）。**機械では止められず、毎回必ず守ってほしいこと**と、**作業ごとにどの資料を読むかの目次** | ルールの中身の説明。ESLint・ls-lint・hook が止めるルール（止められたときに、エラーの文から資料をたどれる） |
| 2. 作業の手順 | その作業をするとき | skill の本文（`SKILL.md`）。全体の流れと、場合ごとにどの詳しい手順を読むか | 場合によって要らない手順の中身 |
| 3. 詳しい手順・ルール | その場合・その節が必要になったとき | skill の `references/`、`docs/` の各資料の該当する節 | - |

- 入口の目次は「作業 → 資料の節」の形で書く（例: 「取得・キャッシュを書く → 04 データ取得・更新の「1」「2」」）。資料名だけでなく節まで示し、長い資料を丸ごと読まずに済むようにする
- 入口にルールを足したくなったら、まず ESLint などで機械的に止められないかを考え、止められないものだけを入口に書く
- skill の本文が長くなったら、場合ごとの手順を `references/` に分け、本文には「どの場合にどれを読むか」だけを残す

## 2. 仕組みの一覧

### 2.1 skill（`.claude/skills/`）

決まった手順の作業を、必要なときだけ読み込む手順書。

| skill | 使う場面 | 中身 |
| ----- | -------- | ---- |
| `add-feature` | 新しい画面、または画面に出すデータ（取得・更新）を追加するとき | 本文（`SKILL.md`）は全体の流れと、場合ごとに読む手順の案内。詳しい手順は `references/` の `backend.md`（バック）・`frontend.md`（フロント）・`mutation.md`（更新がある場合）・`client-fetch.md`（TanStack Query を使う場合）。ルールは `docs/` へのリンク |

- skill は Claude Code を立ち上げたときに読み込まれる。追加・変更したら、次の会話から使える

### 2.2 hook（`.claude/settings.json`、`.claude/hooks/`）

決まったタイミングで、必ず動く処理。

| hook | タイミング | すること |
| ---- | ---------- | -------- |
| ESLint（`eslint-changed-file.mjs`） | ファイルを編集・作成した後（`Edit` / `Write`） | 編集したファイルが `src/` の `.ts` / `.tsx` なら ESLint をかける。エラーがあれば Claude に伝えて直させる |

- 確認や一時的な停止は、Claude Code の `/hooks` から行う

### 2.3 AI 以外でも効く仕組み

AI 専用ではないが、AI の変更も同じように止める仕組み。

| 仕組み | 止めること | 資料 |
| ------ | ---------- | ---- |
| ESLint | 層をまたぐ import、ファイル直下のアロー関数 など | [06 アーキテクチャ](../01_全体設計/06_アーキテクチャ.md) の「依存の向き」、[08 コーディング規約](../02_共通設計/08_コーディング規約.md) |
| ls-lint | ファイル名・フォルダ名のルール違反 | [05 ディレクトリ構成](../01_全体設計/05_ディレクトリ構成.md) の「4」 |
| テスト | 業務のルールとユースケースの誤り。層の説明ページのコード例と実際のコードのずれ | [10 テスト](../02_共通設計/10_テスト.md) |
| CI | 上のすべて（Pull Request ごと） | [11 CI](../02_共通設計/11_CI.md) |

## 3. 仕組みを足すとき

### 3.1 どれを使うか

| やりたいこと | 使うもの | 例 |
| ------------ | -------- | -- |
| 毎回必ず守ってほしく、機械では止められない短いルール | `AGENTS.md` に 1 行足し、詳しくは `docs/` にリンク | 「画面から `fetch("/api/...")` で自前の API を呼ばない」 |
| Claude Code だけの仕組みの案内 | `CLAUDE.md` に 1 行足す | 「画面を追加するときは skill `add-feature` に沿う」 |
| 決まった手順の作業 | skill | 画面を追加する手順 |
| 必ず動かしたい、数秒で終わる処理 | hook | 編集したファイルの ESLint |
| 機械で判定できるルール | ESLint・ls-lint・テスト（AI 以外にも効く） | 層をまたぐ import の禁止 |
| 役割を分けた補助の AI | agents（`.claude/agents/`） | まだ使っていない。必要になってから |

- 機械で判定できるものは、AGENTS.md や skill に書くより、ESLint やテストで止める方を優先する
- `.claude/rules/` は使わない。ルールは `docs/` に 1 か所だけ置く（[ADR-013](../04_設計判断/ADR-013_AI駆動開発の資料.md)）

### 3.2 足すときのルール

- skill・AGENTS.md・CLAUDE.md には手順と案内だけを書き、ルールの中身は `docs/` へのリンクにする（写さない）
- hook は数秒で終わるものにする。ビルドやテスト全体のように時間がかかるものは、作業を終える前に流す（AGENTS.md の「作業を終える前に」）
- hook のスクリプトは Node.js で書く（開発用のコンテナに必ず入っているため。`jq` などは入っていない）
- チームで共有する設定は `.claude/settings.json`（Git で管理する）。個人の設定は `.claude/settings.local.json`（Git で管理しない）
- 足したら、この資料の「2. 仕組みの一覧」に書き足す
