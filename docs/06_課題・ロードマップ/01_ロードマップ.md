# 01 ロードマップ

大きなまとまり（親の Issue）を進める順序と、その目的。書き方は [README](./README.md)。

各課題の中身と状態は GitHub Issues を見る。ここには書かない（ずれるため）。ここを直すのは、まとまりを足す・順序を変える・終わったときだけ。

- 親を持たない Issue（順序を決めていないもの、後でやりたいこと）は、ここに書かない。開いている Issue の一覧（`gh issue list`）で見る
- ずれは、Claude Code に「次は何？」「課題を棚卸しして」と頼むと見つけて直し方の案を出す（skill `issue`）
