# 課題（GitHub Issues）とロードマップを扱う

ルールは `docs/06_課題・ロードマップ/README.md`、コマンドは `docs/06_課題・ロードマップ/02_Issueの作り方.md`。ここには手順だけを書く。

- **何をやるか・どの順でやるかは人が決める。** AI は案を出し、OK をもらってから GitHub に書き込む（Issue の作成・編集・クローズ、ラベル）。書き込みのコマンドは権限で毎回確認が出るが、その前に会話で案を見せて OK をもらう
- 読むだけのコマンド（`gh issue list` / `gh issue view`）は確認なしで使える。何度読んでもよい
- トークンは読まない（`gh auth token` などは権限で止めている）

## 0. gh が使えるか確かめる

```bash
gh auth status
```

ログインしていない・期限が切れているときは、作業を止めて、人に `docs/06_課題・ロードマップ/README.md` の「6.1」の手順でログインし直すよう伝える。トークンを会話に貼らせない。

## 1. Issue を作る（「Issue にして」）

1. 依頼の中身を読み、雛形（`.github/ISSUE_TEMPLATE/` の `feature.md` / `bug.md`）の欄に沿って、タイトル・本文・ラベルの案を作る。足りない情報（不具合の起きる手順など）は人に聞く
2. 似た Issue がないかを探す。あれば、新しく作るか、そちらに足すかを人に聞く

```bash
gh issue list --state all --search "<言葉>" --json number,title,state
```

3. 1 つの Pull Request で終わらない大きさなら、「2」に進む
4. 案（タイトル・本文・ラベル）を見せ、OK をもらう
5. 見せた案のとおりに作る。本文はファイルにせず、標準入力で渡す（一時ファイルを残さない）

```bash
gh issue create --title "<タイトル>" --label <ラベル> --body-file - <<'EOF'
<本文>
EOF
```

6. できた Issue の番号と URL を伝える。親を持たない Issue なら、ロードマップは直さない（順序を決めていない Issue として、Issues の一覧に残る）

## 2. 大きな課題を分ける（「分けて Issue にして」）

1. 親の Issue（目的・全体の完了の条件）と、子の Issue（1 つの Pull Request で終わる大きさ）に分ける案を作る。分け方は README の「3」（層の順に分ける、2 段まで）
2. 次をまとめて見せ、OK をもらう
   - 親と子のタイトル・ラベル・完了の条件
   - 子の着手の順と、依存（どれの後か）
   - ロードマップのどこに入れるか（今あるまとまりの前か後か）
3. 親 → 子の順に作る。子は着手する順に作り、`--parent`・`--blocked-by` を付ける（02 Issue の作り方の「2.3」）
4. **同じ作業の中で**ロードマップの「1. 進める順序」に親を足す。変更履歴にも 1 行足す
5. 作った Issue の一覧と、ロードマップの変更を報告し、ロードマップのコミットを尋ねる（skill `commit`）

## 3. 次にやることを答える（「次は何？」）

1. 先に「4. 棚卸し」の 1〜2 でずれを確かめる。ずれがあれば、答えと一緒に伝える（直すのは OK をもらってから）
2. ロードマップの「1. 進める順序」の一番上の、閉じていないまとまりを見る
3. その親のサブイシューのうち、閉じておらず、`blockedBy` がすべて閉じているものを、並びの順に挙げる

```bash
gh issue view <親の番号> --json number,title,state,subIssues
gh issue list --state open --json number,title,parent,blockedBy,labels,assignees
```

4. ロードマップにまとまりがないとき・すべて終わっているときは、親のない開いている Issue を、`priority:high` を先に、古い順に挙げる
5. 「#◯ から始めるのがおすすめ」と 1 つ示し、人に選んでもらう

## 4. 棚卸し（「課題を棚卸しして」）

1. Issues とロードマップを読む

```bash
gh issue list --state all --limit 300 --json number,title,state,parent,subIssuesSummary,labels
```

ロードマップは `docs/06_課題・ロードマップ/01_ロードマップ.md` を読む。

2. 次のずれを探す

| ずれ | 直し方の案 |
| ---- | ---------- |
| サブイシューを持つ親が、ロードマップの「1」にない | 「1」のどこに入れるかの案 |
| ロードマップの「1」にある親が、閉じている | 「2. 完了したもの」に移す |
| ロードマップの「1」にある番号の Issue がない、または親ではない | 番号の書き間違いか、消すか |
| 親が開いているのに、サブイシューがすべて閉じている | 親を閉じるか（完了の条件を満たしているかを人に聞く） |
| ラベルのない開いている Issue | 付けるラベルの案 |

3. 見つけたずれと直し方の案を表で見せ、どれを直すかを人に選んでもらう。ずれがなければ、そう伝える
4. 選ばれたものだけ直す。ロードマップを直したら変更履歴に 1 行足し、コミットを尋ねる
