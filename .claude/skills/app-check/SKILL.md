# アプリを動かして確かめる

テストとビルドが通っても、画面を開くとエラーになることがある（取得の関数の実行時エラー、`notFound()` の出し忘れなど）。ここでは、ビルドしたアプリを起動して画面を開いて確かめる。

ブラウザでの見た目や、ドラッグなどの操作は確かめられない。報告では「確かめていないこと」に書く。

## 1. ビルドして、結果を見る

```bash
pnpm build
```

最後の `Route (app)` の表で、足した・変えたページの記号が意図どおりかを見る。意図は各画面の `SCR-XXX` の「7.1 取得」に書いてある。

| 記号 | 意味 | こうなるとき |
| ---- | ---- | ------------ |
| ○ | 静的 | 取得の関数に `'use cache'` があるか、データが固定 |
| ◐ | 部分的に静的 | `params` / `searchParams` を読む部分を `<Suspense>` で囲んでいる |
| ƒ | 動的 | Route Handler、または `cookies()` などを使う |

- 一覧が ƒ になっていたら、`'use cache'` の付け忘れを疑う（`docs/02_共通設計/04_データ取得・更新.md` の「2」）

## 2. 起動して画面を開く

[scripts/check-pages.mjs](scripts/check-pages.mjs) を使う。サーバーを起動し、渡したパスを開いて、**終わったら必ずサーバーを止める**。

```bash
# 開けるはずのパスと、404 になるはずのパス（=404 を付ける）を渡す
node .claude/skills/app-check/scripts/check-pages.mjs / /todos /todos/todo-1 /todos/none=404

# ポートが使われていたら --port で変える
node .claude/skills/app-check/scripts/check-pages.mjs --port 3200 /
```

- 足した・変えた画面のすべてのパスを渡す。`[id]` の画面は、ある ID と、ない ID（`=404`）の両方を渡す
- 期待と違う画面があると `NG` と出て、終了コードが 1 になる。サーバーのログにエラーがあれば、最後に出る
- 仮のデータはメモリ上にあるので、ID は `src/server/infrastructure/in-memory/*/in-memory-*-store.ts` の最初のデータから選ぶ

### 知っておくこと

- **`<Suspense>` の中の `notFound()` は、ステータスが 200 のまま 404 の中身を返す**（ストリーミングで、先にステータスを送っているため）。間違いではない。スクリプトは中身（`NEXT_HTTP_ERROR_FALLBACK;404`）で 404 を見分ける
- このコンテナには `ps` と `pkill` がない。サーバーを手で起動した場合も、止めるのはこのスクリプトに任せるか、`/proc/*/cmdline` から `next start` のプロセスを探して `kill` する
- Server Action（登録・更新）は、このスクリプトでは確かめられない。ユースケースのテストで確かめ、画面の操作は「確かめていないこと」に書く

## 3. 使っていない export を見る

```bash
pnpm knip
```

- CI では参考のみ（`docs/02_共通設計/11_CI.md` の「3.3」）。すでにある指摘（導入したがまだ使っていない依存など）で失敗するので、**今回足した・変えたファイルの指摘だけ**を直す
- 使っていない export は、`export` を外すか消す。依存を消すときは、先にユーザーに確かめる
