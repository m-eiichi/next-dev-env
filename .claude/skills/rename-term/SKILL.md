# 画面に出す言葉をそろえて変える

1 つの言葉は、画面の文言だけでなく、エラーメッセージ、コメント、テストの名前、資料、SCR のファイル名にも出てくる。1 か所でも残ると、呼び方がばらばらになる。

## 0. 最初にユーザーに確かめること

- [ ] 新しい言葉。迷っていたら、候補を表にして「おすすめ」を 1 つ示す（印象、ほかの言葉やフォルダ名とぶつからないか）
- [ ] 変える範囲。**おすすめは「日本語の表記だけ変え、URL とコード上の名前（英語）は残す」**
  - URL とコード上の名前まで変えると、フォルダ名・ファイル名・クラス名・キャッシュのタグ名・import がすべて変わり、壊れやすい
  - 英語の名前が、ブラウザや Next.js の名前（`document`、`layout`、`page` など）とぶつからないかも見る
  - コード上の名前も変えるなら、この手順に加えて、`grep` で英語の名前も洗い出す

## 1. 洗い出す

```bash
grep -rn "古い言葉" src docs .claude AGENTS.md CLAUDE.md README.md
```

- 別の意味で使っている所や、長い言葉の一部として出てくる所が混ざる（例:「メモ」で探すと「メモリ」「メモ化」も出る）。1 つずつ見て、変えるものだけを選ぶ
- 採用済みの ADR（`docs/04_設計判断/ADR-*.md`）の本文は書き換えない（`docs/04_設計判断/README.md`）

## 2. 変える

1. 選んだファイルの中の言葉を置き換える
2. 置き換えた後の文を読み、不自然な言い回しを直す（助詞や、説明文の具体例など）
3. SCR のファイル名に言葉が入っていれば、名前を変え（`mv`、コミット済みなら `git mv`）、そのファイルへのリンクを `grep` で探して直す
   - リンクは `docs/` の資料だけでなく、`src/` のコメント（`// 詳細設計: docs/03_画面設計/SCR-...`）にもある
4. 変更履歴を書く。変えた SCR、`docs/01_全体設計/01_サイトマップ・画面一覧.md` の「5. 変更履歴」に 1 行足す（まだコミットしていない、今日作ったばかりの画面なら、書き足さずに置き換えるだけでよい）
5. エラーメッセージを変えたら、テストの `toThrow("...")` の文字列も合わせる

## 3. 仕上げ

- [ ] 洗い出しの `grep` をもう一度流し、残っているのが別の意味のものと ADR だけか確かめる
- [ ] 古いファイル名へのリンクが残っていないか `grep` で確かめる
- [ ] CI と同じチェックを流す

```bash
pnpm lint && pnpm lint:ls && pnpm typecheck && pnpm test:coverage && pnpm build
```

- [ ] ユーザーへの報告に、変えた範囲、変えなかったもの（URL、コード上の名前、ADR）とその理由を書く
